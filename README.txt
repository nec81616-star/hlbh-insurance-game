強制險城市大冒險｜多人版測試說明
==================================

目前已完成的遊戲流程
------------------
學生端：
1. 輸入4位數房號與姓名
2. 選汽車／機車與顏色
3. 選20種角色之一
4. 從該角色5張專屬情境卡隨機抽1張；抽後鎖定
5. 輸入時速，立即取得速度評語
6. READY
7. 老師發車後切換成行車HUD
8. 發生事故時，手機跳出強制險題目
9. 答題後顯示理賠知識與財產／健康／壓力變化
10. 事故處理後重新上路直到終點

老師端：
1. 建立4位數房間
2. 即時看到學生加入、車種、角色、時速、READY狀態
3. 全員READY後「全員發車」解鎖
4. 大螢幕顯示六車道俯視道路與學生車輛
5. 學生設定的時速會真正影響畫面前進速度
6. 五個事件節點會隨機抽：十字路口、壅塞、突發降雨、道路施工、行人穿越
7. 事故判定同時考慮：
   - 玩家時速
   - 情境壓力與分心
   - 車輛機動性
   - 雨天穩定性
   - 道路事件
8. 機動性主要影響「能否避開事故」
9. 防護力主要影響「事故後傷害程度」
10. 事故後跳出強制險知識題，處理後重新上路
11. 抵達時會依情境期限與玩家速度判定是否遲到及額外成本

注意：
「風險值」是遊戲平衡參數，不是真實世界事故機率或統計資料。

第一次設定 Firebase
------------------
A. 建立 Firebase 專案
1. 到 Firebase Console 建立專案。
2. 新增「Web App」。
3. 建立 Realtime Database。
4. Authentication → Sign-in method → 啟用 Anonymous（匿名登入）。

B. Realtime Database 規則
測試版可使用：

{
  "rules": {
    "rooms": {
      "$room": {
        ".read": "auth != null",
        ".write": "auth != null"
      }
    }
  }
}

這是教室測試用規則。正式公開網站若要長期使用，建議再加房主權限與資料驗證。

C. 編輯 firebase-config.js
將 Firebase Console 提供的設定貼進：
window.GAME_FIREBASE_CONFIG = { ... }

databaseURL 要使用你 Realtime Database 實際顯示的網址。


D. Authentication 授權網域
Firebase Authentication → Settings → Authorized domains：
- 若電腦使用 http://localhost:8000，請確認 localhost 已加入授權網域。
- 2025-04-28 之後建立的新 Firebase 專案，不一定會自動加入 localhost。
- 若手機以電腦區網 IP（例如 192.168.1.35）開啟後出現 auth/unauthorized-domain，
  請將實際使用的主機名稱加入 Authorized domains；若校園網路或瀏覽器限制不便處理，
  最穩定的測試方式是部署到 GitHub Pages，並把 GitHub Pages 網域加入 Authorized domains。

一台電腦＋一支手機測試
--------------------
兩台設備都必須能上網，並建議連到同一個 Wi-Fi。

方法1：Windows 電腦用 Python 開本機網站
1. 把整個「強制險城市大冒險_多人版」資料夾放在電腦。
2. 在該資料夾開 CMD。
3. 執行：
   python -m http.server 8000
4. 電腦開：
   http://localhost:8000/teacher.html
5. CMD 執行 ipconfig，找到電腦的 IPv4，例如 192.168.1.35
6. 手機開：
   http://192.168.1.35:8000/student.html
7. 老師端建立房間，例如 2468。
8. 手機輸入 2468 加入。
9. 手機完成造車→角色→抽情境→時速→READY。
10. 電腦看到 1/1 READY 後按「全員發車」。

若手機打不開電腦 IP：
- 檢查 Windows 防火牆是否擋住 Python。
- 確認手機與電腦在同一網路。
- 某些校園 Wi-Fi 會禁止裝置互相連線（Client Isolation）。
  這種情況直接把整個資料夾部署到 GitHub Pages 即可。

遊戲公式（目前版本）
------------------
事件節點風險值會由以下項目疊加：
- 基礎風險
- 時速
- 個人情境壓力
- 個人情境分心
- 事件種類
- 機動性／雨天穩定性修正

事件是否真的發生事故，再用該風險值抽取一次。
所以相同時速並不保證每個人結果都一樣。

事故後：
- 防護力越高，模擬醫療傷害通常較低。
- 車輛維修費會從遊戲財產扣除。
- 強制險知識題答對可增加「保險分」。
- 車輛不會永久淘汰，事故處理後會重新上路。

強制險題目目前涵蓋
----------------
1. 法定給付項目：傷害醫療、失能、死亡；車損不屬法定給付項目。
2. 肇事汽車無法查究等法定情形：汽車交通事故特別補償基金。
3. 酒駕等法定情形：對受害人的給付仍依法處理，但保險人可能依法代位求償。
